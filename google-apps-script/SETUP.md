# ALT-CAM — Google Sheets для заявок

## 1. Створення таблиці

1. Створіть Google-таблицю **ALT-CAM Заявки**.
2. Відкрийте **Розширення → Apps Script**.
3. Замініть вміст `Code.gs` кодом із файла `google-apps-script/Code.gs`.
4. Збережіть проєкт.
5. У списку функцій виберіть `setupAltCamSheet` і натисніть **Виконати**.
6. Підтвердьте доступ до поточної таблиці.

Функція автоматично створить лист **Заявки**, заголовки, список статусів і кольори:

- **Нова** — червоний;
- **В роботі** — помаранчевий;
- **Виконана** — синій.

## 2. Публікація Web App

Перед розгортанням відкрийте **Налаштування проєкту → Властивості скрипта** та додайте:

```text
ALT_CAM_SHEET_ID=1RX1hDhaTDqTE1Oc8GTpoLsXYMK0w1UtFRuYeF9zGLqE
ALT_CAM_MAIL_RELAY_SECRET=<випадковий секрет щонайменше 32 байти>
```

1. Натисніть **Розгорнути → Нове розгортання**.
2. Тип: **Веб-додаток**.
3. Виконувати від імені: **Я**.
4. Доступ: **Усі**.
5. Натисніть **Розгорнути** та скопіюйте URL виду `https://script.google.com/macros/s/.../exec`.

Після зміни коду створюйте **нову версію розгортання**, інакше опублікований Web App залишиться на старій версії.

## 3. Перевірка

Відкрийте URL Web App у браузері. Правильна відповідь:

```json
{"status":"ok","service":"ALT-CAM Sheets intake"}
```

Тестовий POST:

```bash
curl -X POST "GOOGLE_SCRIPT_URL" \
  -H "Content-Type: application/json" \
  -d '{"name":"Тест","phone":"+380000000000","city":"Київ","type":"Консультація","source":"Сайт"}'
```

Після тесту у листі **Заявки** має з’явитися рядок зі статусом **Нова** та унікальним ID.

Для перевірки поштового реле надішліть JSON із полями `kind=email`, `secret`, `recipient`, `subject` і `text`. Секрет не зберігайте в репозиторії та не передавайте у frontend.

## 4. Підключення до сайту

Продакшен-схема для сайту на хостингу:

```text
Сайт (HTTPS) → Render API (HTTPS) → PostgreSQL
                               ├→ Telegram
                               └→ Google Sheets
```

Фронтенд використовуватиме абсолютний URL Render API. Дозволений origin задається змінною `SITE_PUBLIC_ORIGIN` без завершального `/`, наприклад:

```text
https://alt-cam.net.ua
```

URL Apps Script зберігатиметься тільки в середовищі backend як `GOOGLE_SHEETS_WEB_APP_URL`. Це не робить публічний Web App секретним, але не прив’язує форми сайту безпосередньо до Google та дозволяє контролювати валідацію, дублікати й помилки на сервері. Те саме захищене реле створює папки замовлень у Drive від імені власника, якщо сервісний акаунт не має квоти на створення нових файлів.

Для відправлення листів реєстрації та відновлення пароля на Render Free задайте в backend:

```text
EMAIL_RELAY_URL=https://script.google.com/macros/s/.../exec
EMAIL_RELAY_SECRET=<те саме значення ALT_CAM_MAIL_RELAY_SECRET>
```

Backend використовує HTTPS-реле першим. SMTP залишається резервним варіантом для середовищ, де дозволені вихідні SMTP-порти.

Telegram-сповіщення залишаються без змін; Google Sheets працює як додатковий канал і резервна копія.
# Резервний приймач заявок (C-P0-05)

1. Створіть окремий Apps Script і приватну таблицю для резервних заявок.
2. Використайте Code.gs з цієї папки; налаштуйте ідентифікатор таблиці
   за інструкцією нижче та виконайте setupAltCamSheet під власним обліковим записом.
3. Розгорніть вебзастосунок з виконанням від власника та доступом для відвідувачів.
   Це публічний endpoint: можливий спам. Не публікуйте саму таблицю чи секрети.
4. Перевірте тестовий POST з Content-Type: text/plain та JSON з kind: lead_backup,
   client: {name, phone}, message, page. Переконайтеся, що рядок з'явився у таблиці.
5. Лише після перевірки вкажіть HTTPS /exec URL у contacts.js → backupWebhook.
   Порожнє значення повністю вимикає резервний канал. Секретів у contacts.js немає.
6. sendBeacon не підтверджує запис у таблиці. Основне підтвердження заявки
   надходить лише від backend після збереження в базі. Для кошика резервна
   копія містить позиції та доставку, але не запускає відвантаження.
