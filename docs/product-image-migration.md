# Ручной перенос фотографий товаров

Скрипт: `scripts/mirror_product_images.py`. Он НЕ включён в сборку,
GitHub Actions или планировщик. Владелец самостоятельно подтверждает
юридическое право копировать, преобразовывать и публиковать фотографии поставщиков.

## Команды для владельца (агент их автоматически не запускает)

```powershell
# Без сети и без изменений: полный список URL и связанных товаров в stdout.
python scripts/mirror_product_images.py

# Необязательная зависимость только инструмента обработки, не фронтенда.
python -m pip install Pillow

# Пилот: максимум 20 уникальных изображений, без подмены каталога.
python scripts/mirror_product_images.py --download --rights-confirmed --limit 20

# Отдельно разрешённая подмена успешных ссылок; остальные остаются исходными.
python scripts/mirror_product_images.py --download --rights-confirmed --limit 20 --apply
```

Повторный запуск пропускает успешно обработанные изображения, если локальные
файлы существуют. Каждый запуск может скачать следующую партию до limit:
это не режим «только применить». Запускайте только один экземпляр за раз.

Результаты:
- `assets/products/<hash-url>/{480,800,1200}.webp` (фактическая ширина
  меньше целевой для маленького оригинала; увеличения и обрезки нет);
- `output/product-images/manifest.json`: URL, размеры, хеш исходного файла,
  связанные товары и ошибки;
- `output/product-images/<hash>.catalog-backup.js`: исходный каталог перед заменой.

Разрешены только HTTPS-источники viatec.ua и b2b.yugtorg.com. Перенаправления
не выполняются; такие файлы попадут в ошибки для ручного разбора.
Лимит — 15 MiB и 40 млн пикселей на изображение; загрузка последовательная,
с таймаутом, паузой и максимум тремя попытками. Анимированные файлы пропускаются.
Метаданные EXIF не переносятся в WebP.

После пилота проверить качество, прозрачность, общий размер, затем решить,
хранить ли весь объём в репозитории или отдельном хранилище/CDN.
Скрипт меняет только image/images и добавляет image_metadata. ID, slug,
цены, корзину и catalog.html?product=... он не меняет.

## Что ещё требуется перед публикацией

1. Проверить manifest, ошибки, фотографии и наличие резервной копии.
2. Подключить variants из manifest к srcset/sizes, фактические width/height
   к шаблонам. Первое видимое фото — eager, остальные — lazy.
   Сам скрипт шаблоны не меняет.
3. Учесть, что новый импорт поставщика может перезаписать catalog-data.js:
   применение manifest в регулярной сборке требует отдельного согласования.
4. Собрать сайт и проверить фото, OG, JSON-LD и Telegram-превью.
5. Для отката восстановить каталог из резервной копии; файлы фотографий
   автоматически не удаляются.

## Человекочитаемые URL

Пока не меняются. Сначала нужен подтверждённый слой HTTP 301 на CDN/хостинге,
затем постоянный реестр ID → slug, проверка коллизий и миграция sitemap/canonical.
Meta refresh не заменяет HTTP 301. Идентификаторы корзины должны оставаться прежними.
