# Изоляция клиентов

Клиенты общаются только в своих личных чатах. MANAGERS_CHAT_ID — закрытая группа
сотрудников; нельзя добавлять в неё клиентов или размещать приглашение на сайте.
Права кнопок менеджера проверяются по ADMIN_IDS/зарегистрированным владельцам,
а не по членству в группе.

Регрессионные проверки в PostgreSQL-сценарии AI:
- два клиента получают разные ответы, история каждого ограничена его inquiry_id;
- подмена номера заявки в клиентской кнопке и вызов чужой карточки отклоняются;
- ответ менеджера A направляется только A и не приостанавливает AI клиента B;
- история B не содержит сообщения менеджера для A.

Исправления: клиентская кнопка работает только в личном чате её пользователя;
ответ цитатой при активном режиме ответа другой заявке блокируется, FSM очищается.
Неизвестная цитата тоже не отправляется — менеджеру нужно заново выбрать карточку.

Виджет сайта хранит историю в sessionStorage конкретной вкладки; сервер получает
только предоставленную историю, общего буфера разговоров нет. Это не авторизация:
при использовании одной вкладки разными людьми следует закрывать вкладку/очищать
историю. Ссылки корзин и подписанные ссылки подключения заявок не публикуются в
общем клиентском чате. Необязанный ещё Telegram-аккаунту deep-link является секретом
доступа: тот, кому его передали, может привязать заявку первым. Не пересылать такие
ссылки посторонним; для более строгой привязки нужен отдельный OTP-процесс.

Тесты используют вымышленные идентификаторы, локальную disposable PostgreSQL и
поддельные Telegram/LLM-клиенты; реальная клиентская переписка не используется.
